# 住宅代理 vs 資料中心代理：網頁擷取在何時各顯神通？

在設計網絡資料收集架構時，架構師面臨的第一個分水嶺往往是：**買住宅代理，還是買資料中心（機房）代理？**

業界常有一種過度行銷的說法宣稱「機房代理已死，任何業務都必須上住宅 IP」。這完全脫離了工程實際。真實的世界中，**沒有一種代理類型能全能通吃——住宅代理擅長突破嚴格反爬，而機房代理在頻寬吞吐量與單位成本上擁有絕對壓倒性的優勢。**

## 核心維度深度比對

評估指標| 住宅代理（Residential）| 資料中心機房代理（Datacenter）  
---|---|---  
網絡歸屬| 真實家庭用戶光纖或寬頻| 雲端服務商伺服器託管機房（AWS, GCP, OVH）  
消費類站點攔截率| **極低** （自然訪客特徵，難被一刀切）| 較高（主流電商與社群站對機房網段嚴密設防）  
頻寬與回應延遲| 依賴真實寬頻，延遲 100~300ms 不等| **極快極穩** （千兆/萬兆光纖直連，延遲常低於 30ms）  
單 GB 採購成本| 相對較高（需要支付頻寬資源成本）| **極低** （通常按 IP 獨享或大額固定頻寬低價銷售）  
地理覆蓋廣度| 覆蓋全球 200+ 國家與數十萬城市| 通常集中在主要樞紐機房所在城市  
  
## 何時必須選擇住宅代理？

  * **電商大盤與區域價格監控：** 目標站（如 Amazon、Shopee、Walmart）會根據訪客真實住宅歸屬呈現本地化庫存與差異化價格，且對雲端服務商 IP 執行極嚴苛的人機驗證；
  * **社群媒體與旅行機票查詢：** 機票航司站點對非住宅流量極為敏感，機房 IP 請求容易立刻被重導向至驗證碼或偽造假資料頁面；
  * **高並發分散式收集：** 需要成千上萬個互不相同的自然住宅 IP 分攤擷取頻次，避免觸發子網段（Subnet /24）連帶懲處。



## 何時資料中心代理才是更明智的選擇？

  * **擷取自身跨國微服務或合規公開 API：** 若目標系統是合作夥伴明確開放的 API，且允許透過伺服器呼叫，此時使用機房代理可獲得最高的網絡吞吐量與毫秒級回應；
  * **通用無防護站點或低頻監測：** 中小型企業官網、常規新聞門戶等未部署昂貴商業 WAF 的網站，機房代理完全足以勝任，且成本僅為住宅代理的幾分之一；
  * **超大體積靜態檔案下載：** 需要下載大量 PDF、開源資料集或非敏感資源時，高頻寬且不按 GB 計費的機房通道是最具成本效益的選擇。
