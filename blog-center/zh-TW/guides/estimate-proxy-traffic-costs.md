# 如何科學預估短期代理流量（並挑選最合適的 GB 套餐）

在採購動態住宅代理時，許多團隊最容易犯的錯誤就是「用請求次數估算流量」。必須釐清的是：JoyProxy 的動態住宅代理是**按實際經過代理節點的雙向傳輸位元組數計費** ，而非按請求次數。若低估了網頁附帶資源的體積，很容易出現「買了 10 GB 以為能用一個月，結果一個週末就消耗殆盡」的困境。

## 第一步：實測一次真實的單頁流量開銷

切忌只在終端機中用 `curl` 抓取純 HTML 作為計算基準。現代網頁充滿了各類 JS 打包檔、樣式表、字型與非同步 JSON API 呼叫：

  * 在瀏覽器開發者工具（DevTools）網絡面板中，完整載入一次目標頁面，檢視「Transferred（已傳輸）」資料總量；
  * 若爬蟲使用 Playwright 或無頭瀏覽器，必須把頁面觸發的所有子請求都計入統計；
  * 若僅使用 `requests` 或類似輕量客戶端解析原始 HTML，單個頁面的體積可能僅有 100~300 KB；但若渲染完整前端，單個頁面可能膨脹至 1~3 MB 以上。

## 流量成本試算公式示範

假設您每月需要擷取 **50,000 個商品詳情頁** ，實測帶資源完整載入平均體積為 **1.2 MB** ，預估因網絡波動引起的重試率為 **10%** ：

  * 基礎淨資料量：50,000 × 1.2 MB ≈ 60,000 MB = 60 GB；
  * 含重試總開銷：60 GB × (1 + 10%) ≈ **66 GB / 月** ；
  * **採購建議：** 直接採購 100 GB 級距（約 $2.50/GB），不僅能完整覆蓋當月用量，且單價顯著低於多次購買 10 GB 疊加包；未用完的流量在 JoyProxy 帳戶內**永久有效** 。



## 大幅節省代理流量的三條實戰準則

  1. **堅決攔截不必要的媒體資源：** 在爬蟲或無頭瀏覽器中配置路由攔截，主動阻擋 `.jpg`、`.png`、`.mp4`、`.webp`、`.woff` 以及分析統計類第三方腳本；僅保留 HTML 結構與核心 JSON 資料，通常能立竿見影節省 70%~85% 的流量消耗；
  2. **注意連線逾時的底層耗損：** 雖然大部分未連通握手不計入業務資料，但部分建立連線後中途逾時的請求仍會有微量耗損，應設定合理的外層 Timeout（如 10~15 秒）；
  3. **區分動態與靜態產品：** 若特定業務只需要單一 IP 長期維持連線，請購買按時長計費的獨享靜態住宅 IP，切勿使用動態流量包支援長連線工作階段。
